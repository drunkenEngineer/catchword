# The app against section 14, 4 October 2026

Backlog items PERF-1 and RSC-1. Search speed, writing speed and index size at the reference size were measured on 3 October ([2026-10-03-phase0.md](2026-10-03-phase0.md)); this adds the app's start-up and memory, scanning, and embedding in each resource mode.

## Conditions

- **Machine:** the owner's laptop, Intel i7-13620H (16 logical processors), 16 GB of RAM, Windows 11, SSD. It is faster than the spec's reference laptop (four cores, about 2020, 8 GB): every figure below must be measured again on such a machine before release.
- **Build:** release, with the files laid out as the packages install them.

### How each was measured

- **Start-up and idle memory:** `scripts/measure-app.ps1`, three runs. The app logs when its window first asks for the status (`interface.ready`) and when the model is ready (`model.ready`), in milliseconds since the program started. Memory is the private memory of the app and its WebView2 processes, 15 seconds after start, with indexing paused: 162 MB for Catchword itself, with the model loaded, and 150 MB for six WebView2 processes. Their working set adds up to about 505 MB, but it counts pages shared between processes more than once.
- **Scanning:** `cargo test --release -p catchword-service --test measure -- --ignored --nocapture`: 100 folders of 100 notes of about 150 words, words only.
- **Embedding:** `cargo test --release -p catchword-desktop measure_embedding -- --ignored --nocapture`: 120 passages of 300 words, one at a time, as indexing embeds them.

| Mode | Threads | Passages a second |
| --- | ---: | ---: |
| Light | 1 | 5.6 |
| Balanced (default) | 8 | 16.7 |
| Fast | 15 | 17.9 |

- **Indexing peak:** the command-line tool, run from the packaged files, indexing and embedding 300 notes of 700 words: at most 357 MB private, in 60 s. The app's peak is that plus its web view's 150 MB.

## What this means

- **Meaning search arrives 1.7 s after start.** Searches by words work from the first moment; meaning joins when the model is ready. Much of the wait is checking the model's checksums on every start (123 MB of SHA-256) and reading its 25 MB tokenizer. Remembering a good check by file size and date would save most of the first part.
- **Embedding misses 20 a second even here,** as the Phase 0 benchmark found (ADR-20). Fast is barely quicker than Balanced: past eight threads, more cores do not help. The next step is the one section 14 names: batching passages of similar length, which the runtime handles better than one at a time.
- **The model is never released.** The target speaks of memory "with the model released"; the app keeps it loaded (section 12, caching). At 312 MB with it loaded, the target is met anyway.
